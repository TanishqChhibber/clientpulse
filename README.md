# ⚡ ClientPulse

> **Client Reporting SaaS Platform for Digital Marketing Agencies**  
> Integrated natively with **Claude** via Model Context Protocol (**MCP**) over **Streamable HTTP** transport.

---

## 🌟 Overview

**ClientPulse** is a SaaS application built for modern digital marketing agencies. It enables agency teams to manage clients, track campaign performance, compute real-time marketing ROI metrics (CTR, Cost Per Lead, Conversion Rates), maintain historical reporting data, and publish shareable client-facing performance reports.

### 🛡️ Core Architectural Principle: Pure MCP Reasoning
- **Zero AI API Keys**: ClientPulse **never** calls OpenAI, Anthropic, Gemini, or any external AI API directly.
- **Claude as the AI Brain**: All AI reasoning, campaign analysis, performance summaries, and strategic recommendations are generated by **Claude** interfacing directly with ClientPulse via **Model Context Protocol (MCP)**.
- **Bi-directional Synchronization**: When Claude generates or updates reports via MCP, they are immediately persisted to the database and reflect live in the Streamlit frontend.

## 🚀 Quickstart Guide

### 1. Prerequisites & Environment Setup
Clone this repository and ensure Python 3.11+ is installed:

```bash
cd Volopay
python3 -m venv .venv
source .venv/bin/activate
pip install -r clientpulse/requirements.txt
```

### 2. Configure Environment (`.env`)
Copy the example environment configuration:

```bash
cp clientpulse/.env.example clientpulse/.env
```

Contents of `clientpulse/.env`:
```env
# Supabase PostgreSQL Configuration
# If left blank, ClientPulse automatically uses the local SQLite engine
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your-supabase-service-role-key   # server-side only, never expose it to browsers

# MCP Server Configuration
MCP_HOST=127.0.0.1          # use 0.0.0.0 only together with MCP_AUTH_TOKEN
MCP_PORT=8000
MCP_AUTH_TOKEN=             # optional: require "Authorization: Bearer <token>"

# Optional password for the agency dashboard (public share links stay open)
APP_PASSWORD=

# Base URL for public report links
PUBLIC_APP_URL=http://localhost:8501
```

## 🗄️ Supabase PostgreSQL Setup

ClientPulse supports **Supabase PostgreSQL** for cloud-native persistence:

1. Create a free project on [Supabase](https://supabase.com/).
2. Navigate to the **SQL Editor** in your Supabase dashboard (`Dashboard -> SQL Editor -> New Query`).
3. Copy and run the contents of [`clientpulse/schema.sql`](schema.sql). This creates:
   - `clients` table with constraints and indexes.
   - `reports` table with metric tracking and unique share tokens.
   - `activity_logs` table for agency audit trails.
   - Row-Level Security (RLS) policies: the `anon` role can only read published reports; everything else requires an authenticated role. The script can be re-run safely.
4. Copy your **Project URL** and **`service_role` key** (`Project Settings -> API`) into `clientpulse/.env`. The anon key can only read published reports under these policies, so writes would fail.

> 💡 **Zero-Friction Local Mode:** If you do not have Supabase credentials ready, ClientPulse runs out of the box using an automatic local persistent engine (`clientpulse.db`) with identical schema and behaviors.

## 🛠️ MCP Integration & Tool Reference

ClientPulse exposes **6 core tools** over Streamable HTTP transport:

| MCP Tool | Parameters | Description |
| :--- | :--- | :--- |
| `create_client` | `name`, `email`, `industry`, `website`, `notes`, `status` | Registers a new agency client |
| `list_clients` | `status` ('all'\|'active'\|'inactive'), `search` | Retrieves agency clients |
| `create_report` | `client_id`, `title`, `period_start`, `period_end`, `impressions`, `clicks`, `leads`, `spend`, `summary`, `recommendations`, `prev_impressions`, `prev_clicks`, `prev_leads`, `prev_spend`, `status` | Creates campaign report with auto-calculated CTR, CPL, and CVR |
| `list_reports` | `client_id`, `status`, `search` | Lists campaign reports |
| `update_report` | `report_id`, optional `title`, `summary`, `recommendations`, `period_start`, `period_end`, current & `prev_*` metrics, `status` | Updates report and recalculates derived metrics |
| `publish_report` | `report_id` | Marks report published and returns public share URL |
| `set_report_breakdown` | `report_id`, optional `channels`, `campaigns`, `creatives`, `weekly`, `key_insights` | Fills the dashboard's channel split, creative/campaign tables (with Scale/Keep/Cut verdicts), weekly trends and insights panel |
| `get_report` | `report_id` | Returns a report with its breakdowns and insights so Claude can review or refine it |
| `set_custom_dashboard` | `report_id`, `currency`, optional `kpis`, `trend`, `split`, `rankings`, `table`, `reset` | Builds the dashboard around the client's own metrics (e.g. LDAU, ARPU in ₹, D30 retention) instead of ad spend and leads |
| `list_datasets` | optional `client_id` | Lists raw CSV datasets stored in ClientPulse and whether the client has a saved template |
| `upload_dataset` | `client_id`, `name`, `csv_text` | Stores a raw CSV (max 5 MB) so reports can be computed from it |
| `profile_dataset` | `dataset_id` | Column types, ranges, top values and sample rows, so Claude can describe the data |
| `build_report_from_dataset` | `dataset_id`, `title`, `period`, recipe (`metrics`, `kpis`, `trend`, `split`, `rankings`, `table`, `verdicts`…) | ClientPulse computes every number itself (no AI arithmetic), stores the formulas, and saves the recipe as the client's template; omit the recipe to reuse it next month |

## 🤖 Connecting Claude to ClientPulse via MCP

> **Live deployment:** see [DEPLOY.md](DEPLOY.md) for putting the dashboard and MCP server online (Supabase + Render) and connecting Claude through **Settings → Connectors → Add custom connector** with the public `/mcp` URL.

### 1. Claude Desktop Configuration
Open your Claude Desktop configuration file:
- **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`

Add the ClientPulse MCP Server entry:

```json
{
  "mcpServers": {
    "clientpulse": {
      "command": "/absolute/path/to/Volopay/.venv/bin/python",
      "args": [
        "/absolute/path/to/Volopay/clientpulse/mcp_server/server.py",
        "--stdio"
      ]
    }
  }
}
```

Or connect directly to the running remote Streamable HTTP server:

```json
{
  "mcpServers": {
    "clientpulse_remote": {
      "url": "http://127.0.0.1:8000/mcp"
    }
  }
}
```

If `MCP_AUTH_TOKEN` is set, the client must send it as `Authorization: Bearer <token>`.

### 2. Example Prompts for Claude

Once connected, ask Claude naturally:

> **Example 1: Client Onboarding**  
> *"Create a new client in ClientPulse named 'Synthetix Dynamics' in the AI Robotic Automation industry with contact email 'alex@synthetix.io' and target CPL under $30."*

> **Example 2: Campaign Report Generation**  
> *"Generate a Q3 2026 performance report for Synthetix Dynamics. We spent $18,200 on Google Intent Search and Meta Ads, delivered 520,000 impressions, 16,800 clicks, and generated 840 qualified demo requests. Provide an executive analysis and 3 strategic recommendations. Save it as published."*

> **Example 3: Reporting Audit**  
> *"List all current clients and their active reports. Identify the client with the lowest Cost Per Lead and publish their latest report."*

Claude will invoke the real tools on your ClientPulse database, and the results will immediately show in your Streamlit dashboard at [http://localhost:8501](http://localhost:8501)!
